# NVT Signal 역추적 결과

## 결론

차트 https://www.tradingview.com/chart/X3L1Uw1v/ 의 두 번째 열 지표는 gliderfund가 게시한 보호 스크립트 **"NVT (original) - Network Value to Transactions"**(tradingview.com/script/50VFVta2)의 **버전 1**입니다. 스크립트 ID는 `PUB;mGO6NQAZK4oHjEzHPwWWWTIYWDGJkBQF`이며, 네 번째 열은 같은 스크립트의 버전 2(2024-11-05)입니다.

`nvt_signal_reconstructed.pine`은 이 지표를 Pine v6로 재구성한 코드입니다. 차트에서 원본과 재구성 코드의 plot 값을 봉 단위로 추출해 비교한 결과, 13개 경우(59,461행)에서 모든 plot 값과 na 위치, 색상이 10자리 유효숫자 수준까지 일치했습니다.

```
NVT = BITSTAMP:BTCUSD 종가 × QUANDL:BCHAIN/TOTBC / SMA(QUANDL:BCHAIN/ETRVU, 90)
```

- 이동평균은 데이터 심볼 자체의 봉(2009-01부터, 0 값 포함)으로 계산합니다.
- `Force Daily View`를 끄면 차트 시간 단위의 봉으로 계산합니다. 따라서 주봉에서는 90주, 월봉에서는 90개월을 평균합니다.
- 분봉 차트와 `Force Daily View`를 켠 경우에는 모든 값을 일봉에서 가져옵니다.
- 원본이 2011-08-18부터 시작하는 이유는 BITSTAMP 가격 데이터가 그날 시작하기 때문입니다.

## 확정된 규칙

| 항목 | 규칙 |
|---|---|
| 자동 기준선 (상단/하단) | 분봉 200/60, 일봉 계열 150/45, 주봉 계열 450/100, 월봉 1000/333. `Force Daily View`를 켜면 모든 시간 단위에서 150/45입니다. |
| 기준선과 캡 라인 표시 | NVT가 기준선을 넘었고, 해당 Highlight Background 옵션이 켜진 봉에서만 값이 있습니다. |
| 캡 라인 | 차트 봉 365개 구간의 NVT 최고값·최저값(na 제외)입니다. `bar_index < 364`이면 `상단 × 1.1`, `하단 / 1.1`을 씁니다. |
| NVT 선 색상 | 하단 미만 #00FF00, 상단 초과 #FF0000, 그 사이 #474747(Night Mode에서는 #00FFFF) |
| 채우기 색상 | 빨강·녹색, 투명도 90. Night Mode에서는 NVT가 상단을 넘은 봉에서 두 채우기 모두 흰색입니다. |
| 신호선과 교차 | `ta.ema(nvt, 13)`. crossover는 Bullish, crossunder는 Bearish이며, 점은 신호선 값 위치에 찍힙니다. |
| 라벨 | 마지막 봉의 NVT 위치에 "NVT"(labelup, tiny, 투명도 30) |

## 근거

1. **공개 메타데이터**: 입력값의 이름·기본값·순서·최솟값, plot 제목과 순서, 채우기, 색상 팔레트, 숨김 스타일, 라벨 투명도, 알림 6개의 제목과 메시지를 그대로 옮겼습니다.
2. **차트 값 대조**: 4H, 1D, 2D, 5D, 1W, 2W, 1M과 설정 조합 6가지(교차·라벨 표시, Night Mode, Highlight Background 끔, Highlight Areas 끔, Force Daily, Manual Levels)에서 원본과 재구성 코드를 비교했습니다. 불일치는 0건입니다.
3. **독립 데이터 재계산**: 차트와 별개로 확보한 Quandl BCHAIN 원본(QuantConnect 제공, 2009-01 ~ 2021-11)과 BITSTAMP 종가로 NVT를 다시 계산했습니다. 1D 3,737봉 중 3,733봉, 1W 535봉 중 533봉이 원본과 5e-10 이내로 같았습니다. 나머지는 데이터 파일 마지막 며칠의 수정치입니다. 차트 종가를 쓰면 중앙 오차가 0.15%, 최대 오차가 50%로 커지므로, 가격 기준은 BITSTAMP로 확정됩니다.

## 한계와 주의 사항

- **데이터 피드 상태**: 2026-09에는 `QUANDL:BCHAIN/ETRVU`와 `TOTBC`, 그리고 이름만 다르고 데이터가 같은 `BCHAIN:*` 피드에 2026-06-22 이후 봉이 없었습니다. 그래서 그 이후의 NVT는 원본과 재구성 코드 모두 "BITSTAMP 종가 × 상수"였습니다. 2026-11-12에는 `BCHAIN:ETRVU`와 `TOTBC`에 2026-11-11까지 봉이 다시 들어와 있었습니다(아래 "리페인트 점검" 참고). 원본을 차트에서 실행한 값이 `BCHAIN:*` 데이터로 다시 계산한 값과 일치하므로, 두 피드는 지금도 같은 데이터로 보입니다. TradingView 공식 레퍼런스에는 QUANDL 요청이 더 이상 유효하지 않다고 적혀 있으므로, 앞으로는 두 지표 모두 오류로 멈출 수 있습니다.
- **최종 수정분의 차트 실행 여부**: 여러 시간 단위에서 완전 일치를 확인한 것은 Cowork가 만든 v4입니다. 최종 코드는 v4에 메타데이터 항목(알림 6개, 입력 최솟값, 숨김 스타일, 라벨 투명도, precision 제거)과 리페인트 방지 옵션을 더했습니다. 2026-11-12에 최종 코드를 TradingView에서 실행했고, 옵션을 끈 상태의 1M 닫힌 봉 값이 원본과 같았습니다. 다른 시간 단위에서는 다시 실행하지 않았습니다.
- **알림 조건**: 알림의 제목과 메시지는 메타데이터에서 가져왔지만, 조건식은 제목에서 추론했습니다. plot 값으로는 검증할 수 없습니다.
- **검증하지 않은 경우**: INDEX:BTCUSD 이외의 차트(특히 USD가 아닌 차트), 틱 차트, 3M 이상의 월봉(이동평균이 계산되지 않아 값이 없음), Highlight 옵션을 하나만 끈 경우, Night Mode와 Highlight 옵션을 함께 바꾼 경우입니다.

## 4열 지표 (같은 스크립트의 v2)

4열은 같은 스크립트의 버전 2(2024-11-05)입니다. 작성자가 Quandl 대신 온체인 전송량을 쓰도록 바꾼 버전이며, `nvt_signal_v2_reconstructed.pine`으로 재구성했습니다.

```
NVT = GLASSNODE:BTC_MARKETCAP / SMA(GLASSNODE:BTC_TOTALVOLUMEUSD, Transaction Period)
```

- 두 값 모두 차트 시간 단위의 봉으로 가져옵니다. 1D 6,109봉, 1W 836봉, Transaction Period 30인 1D에서 모두 원본과 일치했습니다.
- Glassnode 데이터는 약 2일 늦게 갱신되므로, 마지막 봉 몇 개는 같은 값이 반복됩니다.
- 분모인 Glassnode 총 전송량은 blockchain.com 추정 거래량(ETRVU)보다 대체로 5~10배 큽니다. 그래서 값의 크기가 v1의 약 1/10이고, 45/150 같은 v1 기준선은 적용되지 않습니다.
- 알림의 조건식과 메시지, `Force Daily View`의 동작은 추정입니다.

## 리페인트 점검 (2026-11-12)

9월에 기록한 값과 2026-11-12에 받은 데이터로 다시 계산한 값을 비교했습니다. 원본 v1을 차트에서 실행한 월봉 값도 재계산 값과 124개월 모두 일치했으므로, 원본과 재구성 코드는 똑같이 바뀌었습니다. 코드가 미래 데이터를 쓰는 문제는 없으며, 원인은 입력 데이터에 있습니다.

### v1 (2열): 입력 데이터가 바뀌었습니다

- **피드 공백이 채워졌습니다.** 9월에는 2026-06-22 이후 봉이 없었지만, 지금은 2026-06-23 ~ 11-11의 실제 일별 값이 들어 있습니다. 0이나 같은 값의 반복이 없고, 공급량이 하루 평균 약 450 BTC씩 늘어나므로 실제 데이터로 판단합니다. 그래서 이 구간의 값이 모두 바뀌었습니다. 월봉 기준으로 6월 -3.9%, 7월 -6.6%, 8월 -8.1%, 9월 -10.1%이고, 주봉은 15~23% 올라갔습니다.
- **과거 거래량(ETRVU) 값이 수정되었습니다.** 2016~2023년의 값이 조금씩 수정되었습니다. 중앙값은 0.25%이고, 큰 것은 2017-12-31이 -5.7%, 2020-02-29가 -49%입니다. 2025-09-30, 2025-10-31, 2026-01-31처럼 9월에는 없던 날짜가 지금은 채워진 것으로 보이는 경우도 있습니다. 월봉과 주봉은 90봉 이동평균에 이 값들이 들어가므로, 닫힌 월봉 120개(2016-06 ~ 2026-05)가 모두 -4.0% ~ +1.6%(평균 -0.15%) 바뀌었습니다.
- **공급량(TOTBC)과 BITSTAMP 가격은 바뀌지 않았습니다.** 수정된 달이 이동평균에 들어갈 때 생긴 차이가 정확히 90개월 뒤에 반대 부호로 빠져나갑니다(상관계수 -0.9999). 이 패턴은 거래량 값의 수정으로만 설명됩니다.
- **화면에서 바뀐 부분**: 월봉(1000/333)에서는 2016-12, 2026-01, 2026-09가 회색에서 초록으로 바뀌었고, 하락 교차가 2025-11에서 2025-10으로 옮겨졌습니다. 주봉(450/100)에서는 2026-08-31, 09-14, 09-21이 회색에서 빨강으로 바뀌었습니다. 일봉은 9월의 전체 기록이 없어서 과거 구간의 색 변화를 셀 수 없습니다.

### v2 (4열): 마지막 봉만 바뀝니다

닫힌 봉은 9월 값과 모두 같습니다(차이 4e-6% 이하). Glassnode 데이터가 늦게 들어오는 마지막 1~2개 봉만 바뀝니다.

### 평소에도 생기는 리페인트

온체인 데이터는 늦게 발표됩니다. BCHAIN은 약 1일, Glassnode는 약 2일 늦습니다. TradingView는 아직 없는 날의 값을 직전 값으로 채워서 그렸다가, 데이터가 들어온 뒤 차트를 다시 불러오면 그날의 값으로 다시 계산합니다. 그래서 이미 닫힌 봉도 나중에 바뀝니다.

- 2025-01 ~ 2026-11을 날마다 재현해 보면, 1D에서 v1은 마지막 봉이 평균 0.57% 바뀌었고, v2는 마지막 두 봉이 평균 2.45%와 1.65% 바뀌었습니다(최대 -17.4%).
- 1W와 1M도 마감된 봉의 거래량이 하루치 값이므로, 그날 값이 늦게 들어오면 방금 닫힌 봉이 바뀝니다.
- 4H 같은 분봉에서 v1은 일봉 값을 가져옵니다. 실시간으로 지켜본 봉은 실시간 가격을 쓰지만, 다시 불러온 봉은 전날 값을 쓰므로 하루씩 늦은 계단 모양이 됩니다.

### 리페인트 방지 옵션

두 파일에 `Non-repainting (use confirmed on-chain data only)` 입력을 추가했습니다. 기본값은 꺼짐이며, 꺼 두면 모든 plot이 원본과 같습니다.

- 켜면 각 봉은 봉의 마지막 날보다 `On-chain publication lag (days)`일 이전 날짜의 온체인 값만 씁니다. 이 값은 봉이 닫힐 때 이미 발표되어 있으므로, 과거 봉과 실시간 봉이 같은 날짜의 값을 고르게 됩니다.
- 기본 지연은 v1 2일, v2 3일입니다. 발표 지연의 최솟값(v1 1일, v2 2일)보다 하루 더 길게 잡아서, 공급사가 하루를 빠뜨리거나 늦게 올려도 닫힌 봉이 바뀌지 않게 했습니다. 최솟값으로 설정하면 각 봉은 원본이 마감 시점에 실시간으로 보여준 값을 그대로 유지합니다. 최솟값보다 작은 값은 입력할 수 없습니다.
- 데이터가 아직 확정되지 않은 닫힌 봉은 값을 비우고 회색 배경으로 표시합니다. 진행 중인 봉에는 임시 값을 표시합니다.
- 선이 지연 일수만큼 늦어지는 대가가 있습니다. 2016년 이후 원본과 벌어지는 정도(중앙값)는 v1 1D 0.84%, 1M 1.16%, v2 1D 3.07%입니다. v1 주봉(Force Daily 끔)은 지연 2일이면 일요일 대신 금요일 거래량을 쓰므로 원본보다 평균 1.7% 낮게 나옵니다. 주봉에서는 지연 1일이 거의 치우치지 않습니다(-0.18%).
- 공급사가 이미 발표한 과거 값을 수정하거나 공백을 나중에 채우는 경우는 막을 수 없습니다. 이번 v1의 변화가 여기에 해당합니다. 공급사가 지연 일수보다 더 늦으면, 회색 봉이 나중에 값으로 채워집니다.
- TradingView 컴파일에서 오류와 경고가 0건이었고, pynescript 파싱도 통과했습니다. 옵션을 켠 동작은 시점별 재현(에뮬레이터)에서 확인했으며, 닫힌 봉의 값이 바뀐 경우는 0건이었습니다. 실제 차트에서 실시간으로 지켜보지는 않았으므로, 옵션을 켠 상태에서 최근 닫힌 봉 몇 개의 값을 적어 두었다가 1~2일 뒤에 다시 불러와 비교해 보기를 권합니다. 알림은 "Once Per Bar Close"로 설정하는 것이 좋습니다.
